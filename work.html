African Fintech Checkout Latency

Payment platform • Kenya & Nigeria • 2026
380ms → 95ms
p99 latency reduction

A payment platform serving Kenya and Nigeria saw 40% drop-off at checkout during peak traffic. Their API averaged 380ms TTFB from Nairobi. Users on 3G simply timed out.

Diagnosis

  • DNS resolving through Google DNS London, then to authoritative NS in Virginia
  • TLS 1.2 full handshake requiring two round-trips across the Atlantic
  • No CDN edge caching for API responses; every request hit origin in us-east-1
  • BGP path: Safaricom → SEACOM → London IX → AWS (18 hops, congested)

Fix

nginx.conf — TLS 1.3 + 0-RTT
ssl_protocols TLSv1.3;
ssl_early_data on;
ssl_ciphers TLS_AES_256_GCM_SHA384:TLS_CHACHA20_POLY1305_SHA256;
resolver 1.1.1.1 1.0.0.1 valid=300s;
add_header Alt-Svc 'h3=":443"; ma=86400';

Result

Metric Before After Change
DNS Resolution 120ms 15ms -87%
TLS Handshake 180ms 45ms -75%
TTFB 380ms 95ms -75%
p99 Latency 420ms 110ms -74%

AWS Infrastructure Cost Optimization

Series A fintech • East Africa • 2026
-35%
Monthly cloud spend

A scaling fintech was burning $18,000/month on AWS with no reserved instance strategy, oversized EC2 instances, and unoptimized S3 storage tiers. Their engineering team was too busy shipping features to audit infrastructure.

Fix

  • Right-sized EC2 instances (m5.2xlarge → m5.xlarge with auto-scaling)
  • 3-year reserved instances for baseline compute (40% savings)
  • S3 Intelligent-Tiering for log storage (60% storage cost reduction)
  • CloudFront caching layer to reduce origin load

"The audit paid for itself in the first month. We reinvested the savings into engineering hires."
