Scoring methodology

How we score

AfricaLatency keeps browser lab scores separate from live network measurements. Scores are calculated from the selected device profile and the report shows the test conditions used.

Performance

Performance is the Lighthouse Performance category score, unchanged, converted from 0–1 to 0–100%. We do not modify the Lighthouse score.

Structure

Structure is AfricaLatency's own composite, not a Lighthouse or GTmetrix score. It combines Lighthouse Best Practices (40%), SEO (35%), and selected accessibility audits (25%). The selected audits are color contrast, image alt text, form labels, link names, button names, document title, HTML language, and viewport metadata. Available audit scores are weighted by Lighthouse audit weight; not-applicable audits are omitted and the remaining weights are renormalized. If the selected accessibility audits are unavailable, the Lighthouse Accessibility category is used instead. If a category is unavailable, the remaining category weights are renormalized.

Overall grade

We calculate the composite score as 70% Performance + 30% Structure, then map it to a letter grade:

  • A: 90–100
  • B: 80–89
  • C: 70–79
  • D: 60–69
  • F: below 60

If either Performance or Structure is unavailable, no overall grade is shown.

Core Web Vitals and timings

We display Lighthouse's LCP, TBT, CLS, FCP and TTFB audit values. Missing metrics remain unavailable. Mobile runs use Lighthouse's simulated mobile throttling by default; Desktop runs use desktop settings. Signed-in users receive the median of three sequential Lighthouse runs to reduce the influence of run-to-run variation.

African network latency

Globalping ping measurements are displayed separately from Lighthouse. RTT is reported only for completed probe results. Countries without a matching probe or completed result are labelled unavailable and are excluded from the median. This is a point-in-time sample, not a country-wide or ISP-wide average.
