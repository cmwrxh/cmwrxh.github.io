# AfricaLatency RUM Beta MVP

## Current status
The RUM beta uses the existing AfricaLatency Supabase project, `uzihwtxffklisczqvurf`. Do not create a second Supabase project or branch for this workflow. The existing project already contains the `rum_beta_*` schema and functions; do not reapply `sql/rum-beta-mvp.sql` or make schema changes as part of dashboard integration.

Preview application verification must use the same Supabase project, with the deployment's public URL/key supplied through `/api/rum-config`. Keep the browser configuration deployment-driven: `SUPABASE_PUBLIC_URL` overrides `SUPABASE_URL` when the server uses an internal service URL, and the public key comes from `SUPABASE_PUBLISHABLE_KEY` or `SUPABASE_ANON_KEY`. The service-role/secret key must never be returned to the browser.

The beta dashboard reads only `rum_beta_sites` and `rum_beta_events`. Existing rows in the legacy `rum_sites` / `rum_events` tables are not automatically backfilled or displayed by this workflow.

Because preview and production share the database, do not use real customer accounts or customer sites for tests. Use an explicitly designated test account and clearly named `test-*` RUM site/domain. Do not run destructive cleanup, delete existing RUM data, or modify schema/credentials during verification. If a safe test account and hostname are not available, limit verification to CI and mocked/local checks until they are provided.

## Data flow
- Customer embeds the site-specific snippet generated by the authenticated RUM dashboard.
- First-party snippet loads the self-hosted Google `web-vitals` IIFE bundle from `/api/rum-library`, records LCP, INP, CLS and TTFB, and sends sampled events with `navigator.sendBeacon`.
- No cookies or local storage are used by the snippet. Event payload contains metric name/value, normalized pathname only, and connection type where available. It excludes the full URL, query string, raw user agent, user ID and IP address.
- Ingest checks the public key, exact Origin hostname allowlist, active site and per-key hourly request limit.
- Country and ASN/network organization are resolved using local MaxMind GeoLite2 Country and ASN MMDB files mounted at `/app/data/GeoLite2-Country.mmdb` and `/app/data/GeoLite2-ASN.mmdb`. The IP is used transiently for lookup, never inserted into RUM tables or logged by this endpoint.
- Authenticated dashboard uses the current deployment's Supabase public configuration, Supabase sessions and owner checks. SQL aggregation returns site-wide p75 and sample counts plus country/operator/connection breakdowns. Each group is suppressed below 30 samples.
- Customers can delete a site only after an owner-scoped lookup; deleting the site cascades to its stored events. The UI requires confirmation and reports success only after the API confirms deletion.
- The consolidated migration defines a retention function, but no retention or monitoring job is to be scheduled as part of this work. Monitoring and all scheduled jobs remain on hold.

## Kenya privacy
Engineering summary, not legal advice. Kenya's Data Protection Act 2019 and ODPC guidance require transparent, lawful, purpose-limited processing and safeguards. Even when raw IP is not retained, the server receives an IP and uses it transiently for GeoIP lookup; do not describe that as “no IP processing.” Site owners must provide an appropriate visitor notice and assess their lawful basis and cross-border processing. Update AfricaLatency's policy before production activation.

## Launch gates
1. Verify the preview deployment's `/api/rum-config` resolves to the existing AfricaLatency Supabase project and returns only its public key; never expose the service-role/secret key.
2. Confirm the existing `rum_beta_*` tables, RLS and RPC grants are present. Do not apply the migration again.
3. Mount current GeoLite2 Country and ASN MMDBs at `/app/data`; verify account/license, attribution, update cadence and old-file deletion.
4. Install `maxmind` and `web-vitals`; verify gzip size of `rum.js` is under 3 KB and the library is self-hosted.
5. Test site creation using an explicitly designated test account and a clearly named `test-*` site on an approved test hostname. Do not create test records under a customer account.
6. Send real browser vitals only from that approved test hostname; verify rows contain no IP/full URL/query/UA/user IDs.
7. Validate p75 values and suppression under 30 samples. Do not manufacture events or claim live customer data.
8. Test owner isolation with two designated test accounts if available; verify one account cannot read/delete the other's site. Delete only test records created for this test and only after recording the result.
9. Do not create or enable scheduled jobs. Retention scheduling is explicitly deferred.
10. Test dashboard at 390px and 1440px and retain genuine screenshots.
11. Enable the AfricaLatency site's own RUM snippet only after a real site key is registered and the ingestion/privacy checks pass.
